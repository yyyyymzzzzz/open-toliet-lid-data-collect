## 完整采集流程

1. **准备**：按用户配置机械固定夹爪；确认两路画面、关节反馈、空间正常。底盘停稳，停止其它程序的机械臂控制输出。
2. **启用手动会话**：直接点击启用，无需重复勾选。此步只建立SDK会话、读取状态与范围，不运动。
3. **开始拖动示教**：手动点击后启用精确力控拖动，同时记录关节轨迹。手动完成任务。
4. **结束示教**：退出拖动、检查SDK返回及连续0.5秒新鲜关节稳定，保存合格轨迹。不会自动归位。
5. **沿轨迹返回起点**：现场确认路径清空后手动点击。当前位置必须在本条示教终点2°内；只对≤2°偏差执行受限低速对齐，然后沿该轨迹逆序返回，不使用旧机器人home。
6. **回放并采集**：手动点击后正向回放，同时保存真实双相机和状态。成功结束后保持待审核；任何中止/守卫错误都会使该条不能作为成功示教。
7. **回看与接受**：逐帧检查画面、实际源帧率、关节与间隙，确认任务实际成功后才点接受。拒绝仅改标记，不删除原始文件。
8. **释放手动会话后导出**：只导出已接受、质量PASS、非诊断且全程满足夹爪策略的样本。

也可以使用“实时采集”页被动录制，通过现场既有控制方式操作；其录制开始/结束按钮只控制数据，不是机械臂停止按钮。

## 手动控制的限制

- 所有运动按钮由现场人员触发。没有自动启用会话或自动回放。底盘和夹爪没有运动输出。
- 5秒控制租约：本页可见并持续续期时保持；离开/关闭页面后停止续期，后台停止。软件停止不是硬件急停。
- 必须观察到其它控制器idle、dispatch计数不变，以及新鲜关节、力和力矩；遇到其它控制输出、报警或反馈过期立即取消。
- 沿用部署URDF与SDK实际限位的交集。额外守卫：20N、3Nm、150ms反馈、3°跟踪误差；不写工具坐标、FT零点、标定或放宽硬件保护。
- 目标125Hz，默认0.25倍回放；每步≤1°、速度≤10°/s、加速度≤30°/s²。迟到>50ms停止，不补发。SDK/系统调度可能让实际速度更慢。
- 示教最多140秒，回放目标约≤560秒；路径尖角或时间断档会被拒绝。起终点应有短暂停稳。≤2°端点对齐使用quintic小段，独立保存审计，原示教路径不改写。
- 停止流程先撤销发令票据，再退出拖动/SDK slow-stop，核对返回码和新鲜反馈停稳。无法确认时锁为FAULT；原生SDK阻塞无法由Python强制终止，此时需现场硬件停止并检查。
- 故障不会自动恢复运动。确认现场停稳、排除原因后可手动重启面板服务；重启后仍是未启用会话，夹爪沿用用户配置。
- **真实机械臂拖动/返回/回放尚未进行现场动作验收。软件测试通过不代表开盖任务成功。**

## 原始示教保存与回放时序解耦

结束示教先把原始关节样本原子写入数据盘JSON，再评估回放。超出回放速度/加速度不再导致原始路径丢失；不完整或有采样空洞的记录也保留并明确标记不可回放。最新路径指针`manual_motion/latest_teaching.json`用于服务重启后恢复显示，启用会话时按当前实际限位重新检查，不自动运动。

回放采用逐原始相邻关节样本的quintic时间参数化：所有原始waypoint保留、每段仍为相同关节空间直线，段内无超调；只延长时间，使速度、加速度和单步满足当前保护。每个waypoint速度/加速度归零，可能比选择倍率更慢。UI显示预计轨迹段回放时长；端点对齐时间另计。总轨迹段超过555秒、缺失/非法数据或超出关节限位时仍拒绝执行，但原始JSON保留。

故障或手动停止中断的拖动以complete=false保存，不能被当作完整可执行示教；正常结束则complete=true。训练集仍只来自后续合格录制、人工接受与导出，关节路径JSON本身不是完整双相机训练数据。

## 返回/回放离线规划隔离

回放插值、完整指令验证和大URDF网格序列化改在独立低优先级纯计算进程中执行，避免与ROS订阅、SDK报警读取和会话续期争用主服务Python解释器。规划期间仍保持ARMED与心跳，ready=false；停止会取消当前操作代数，迟到计划不能启动运动。发令前重新检查关节位置（规划期间偏移>0.1°则要求停稳重试）、控制器和当前owner。

当前455帧原始路径保持不变。真实机器人主机纯离线规划得到18109个125Hz命令点，主进程20ms监测tick最大间隔约20.4ms；未由Agent执行该路径。原始JSON/自定义零位不会在更新时被改写。

## 最新报警反馈：复用现有rm_driver UDP

新增TCP轮询连接在真机拖动期间出现状态查询及停止命令-2；停止新增只读轮询后，一次软件停止重试成功并确认关节停稳。现改用原rm_driver已有 `/rm_driver/udp_rm_err`、`udp_joint_error_code`、`udp_joint_en_flag` 话题，结合现有最新关节反馈，不再启动ControllerTelemetry的TCP轮询子进程。

`ros_controller_telemetry.py`校验三路反馈完整性/150ms新鲜度、系统与六关节报警和使能状态；缺失/过期仍拒绝，不伪造停止成功。停止仍要求退出拖动与slow-stop均成功以及实测停稳；仅最后报警复核改用UDP，不再额外发get_current_arm_state轮询。原controller_telemetry.py保留为历史诊断源码，生产默认不使用。

## 限位依据与停止确认修复

当前机械臂SDK读回J5范围为-178°～300°，而部署URDF写30°～300°。已确认在J5约29.25°时控制器无报警，先前误停来自面板取URDF/SDK交集。面板现从控制器rm_get_joint_min_pos/max_pos读取实际六关节限位并据此校验，URDF仅保留为模型信息，未写控制器限位、未修改URDF文件。界面启用会话后显示实际控制器限位；已保存零位保持不变。

停止确认只判断停止命令回执、新鲜有限关节是否稳定、报警状态，不因位置处在命令范围外便把已停误写成未停。真正超出控制器范围仍禁止继续运动/恢复。首个故障独立记录，后续停止错误最多附加一次，不再递归拼接。

## 默认1×与发送时钟修复

默认回放请求倍率改为1×，界面和后台一致；当前用户配置的replay_speed也设为1，其它参数保留。1×是请求时间尺度，保形时序仍可能因速度/加速度/单步限制自动变慢，以页面预计回放时长为准。

发送线程的50ms门槛改为短暂抖动记录：50～150ms内延迟不跳点、不补发，后续时间轴顺延，较慢SDK调用结束后至少等待一个发送周期。正常低延迟时仍以125Hz调度。命令流间隙或SDK调用超过150ms仍停止；独立ROS/UDP反馈、跟踪误差、关节/力矩和lease检查不取消。playback_timing记录延后次数及最大迟到/SDK耗时。

## 最新回放方式：MoveJ返回与原时间戳回放

用户明确要求取消逐点规划。`home`按钮现在为单次SDK MoveJ直达最新示教起点，使用当前复位速度百分比；不是沿原轨迹倒放，路径可能不同，须由现场按钮明确触发。自定义零位仍是独立reset目标，未被改写。

整段replay使用原始时间戳与线性插值，默认1×，只在125Hz采样末尾向上取整不足8ms；不在每个样本点停下，不自动加长整段时序。必要的起点小偏差对齐单独计时。沿用短暂调度抖动顺延、不跳点不追赶；长停顿仍停止。
